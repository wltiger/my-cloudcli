# Rewind happens by re-sending a message, so there is no rewind state to store

Claude's `resumeSessionAt` is an option on the next query rather than an operation of its own: clicking Rewind changes nothing on disk until a message is actually sent. Rewind is therefore defined as a single gesture that ends in a send — the composer is prefilled from the chosen message (text and attachments), the messages that would leave the context are dimmed, and nothing has happened until send is pressed. There is deliberately no rewind-anchor table; adding one would reintroduce a CloudCLI-side copy of state the provider owns.

**Considered Options**: persisting a pending anchor per session so the intervening state survives a reload — rejected, a session could then sit "rewound but not sent" indefinitely, rendering truncated in CloudCLI and complete in Claude Code's own CLI. Frontend-only optimistic truncation with no persistence — rejected, a reload silently undoes it and it reads as a bug. Letting OpenCode keep its native standalone shape, since `revert` there is immediate and durable — rejected so one gesture does not mean two different things; on OpenCode the revert is issued at send time and rolled back with `/unrevert` if the send fails.

# Antigravity permissions are granted in the user's own project record

Headless `agy` cannot prompt: a tool needing permission is auto-denied, and the run still exits 0 with `result.status: "SUCCESS"` — the only trace is an empty `response` and a populated `denied_actions`, so a caller reading status alone reports a refusal as a success. Pre-granting is the only lever, and grants are project-scoped: `cli.log` shows the CLI loading the shared `~/.gemini/config/config.json` grants and then, on `ApplyProjectPermissionGrants: no grants for project "CLI Project"`, clearing them again. So CloudCLI resolves each Project to the Antigravity project whose `folderUri` covers it — creating one only when none exists — selects it with `--project`, and writes allow rules into that record's `permissionGrants`. A denied action becomes a one-click rule, exactly as `ClaudePermissionSuggestion` already does for Claude. Matching is exact: `command(echo)` does not cover `echo hello`, so a rule names the whole command.

**Consequences**: CloudCLI writes to a record the Antigravity IDE and the user's own terminal also own. That is deliberate — the same relationship the fork already has with `mcp_config.json` — and it is what makes a grant given in the IDE apply here and vice versa; isolating CloudCLI in its own `cloudcli-*` projects would have meant granting everything twice. `--project` also replaces `--add-dir` as the project key, which is what makes a session attributable at all.

**Considered Options**: offering all four permission modes for parity with the other providers — rejected, `--mode accept-edits` and `--mode plan` are accepted and then ignored in print mode with a warning, so listing them would hand a reader a mode that silently does nothing. Only `default` and `bypassPermissions` survive that, and `supportsPermissionRequests` is false alongside them. Simulating `acceptEdits` by writing a transient `write_file(*)` grant for the duration of a run — rejected, it mutates a record the IDE may be holding open, and a crash would leave the permission permanently on.

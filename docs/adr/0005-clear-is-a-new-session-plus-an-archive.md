# Clear is a new session plus an archive, not a rewind to zero

Rewinding to a genuinely empty conversation was measured to be impossible on Claude: `resumeSessionAt` fails hard on any uuid it cannot resolve (`No message found with message.uuid of: …`, returned as `error_during_execution`), and the first user message in a transcript carries `parentUuid: null` — there is no row before it to anchor on. Clear is therefore its own operation rather than the limiting case of Rewind: it opens a new empty session in the same project, archives the session it replaces, and prefixes that session's title so the retired conversation stays identifiable in the sidebar. This supersedes ADR 0003, which planned to ship Clear with Rewind and left exactly this question open.

**Considered Options**: making Clear provider-native — OpenCode's `POST /session/{id}/revert` against the first message does reach an empty conversation under the same session id, so on that provider Clear could have been in place and even undoable via `/unrevert`; rejected because Claude cannot match it, and one button that adds a sidebar entry on one provider but not the other is worse than a uniform one. Deleting the replaced session rather than archiving it — rejected, the conversation being retired is usually the one worth keeping.
